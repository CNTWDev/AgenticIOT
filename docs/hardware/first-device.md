# 首个真实设备接入计划

状态：接入方案草案，等待用户确认设备。尚未实施真实驱动或进行硬件验收。  
日期：2026-09-14

## 本轮只做什么

只接一个明确型号、固件版本和测试用途的设备。先验证身份与只读观测，再单独批准一个低风险动作；不扩展成通用设备配置中心、自动发现系统或新的 Agent 平台。

**当前缺少的唯一启动信息：首个设备的品牌、型号和已知接入协议。** 不需要提供密码、令牌、家庭地址或账户资料。确认设备后再核对厂商一手协议文档、测试环境和能力范围。

现有 `mqtt-light-demo-v1` 是自定义模拟灯具协议，不兼容任意 MQTT 产品。真实设备不一定有亮度能力，不能为套用当前模板而补造属性、观测或动作。`simulated: true` 限制保持不变；不能通过改一个标志把演示驱动变成真实驱动。

## 三个交付阶段

| 阶段 | 交付 | 放行条件 | 当前状态 |
|---|---|---|---|
| A：确认设备 | 一份型号/固件固定的接入卡、官方协议依据、能力映射 | 用户确认目标和用途；协议、读回与认证方式已核实 | 等待型号 |
| B：只读验证 | 该型号专用只读 Adapter、隔离测试环境、观测证据 | 设备身份与访问权限有效；旧值/断线不冒充新观测；无控制权限 | 未开始 |
| C：受控执行 | 一个绝对设值动作、故障验收、停机办法 | B 通过；用户明确批准设备/动作/测试窗口；故障矩阵通过 | 禁止执行 |

这些是交付门槛，**不是已经实现的新 API、数据库状态或硬件安全认证**。计划文件或勾选清单不能激活任何设备。第 B 阶段之前先评审模拟/真实状态在 API、存储和界面中的区分，再开发，不把物理观测贴成模拟数据。

| 字段 | 当前值 / 填写要求 |

| 原生命令关联 / 去重 | 设备是否支持 request ID、重复检测、重启后持久化；未知不能当支持 |
| 状态与时间证据 | 原生采样时间/序号或 Edge 接收时间；必须区分，不能伪造设备采样时间 |

| 设备身份与认证 | 可验证身份、配对方式、凭证更新/撤销；仅 IP、MAC、主题名不足以证明身份 |
| 连接配置 | 精确 endpoint、端口、设备地址/主题、证书信任锚和版本；仅留在受限运维配置 |

含设备地址/序列号等运维信息的实际接入卡保存在受限位置，不提交本仓库；仓库仅保存不含秘密的型号模板与脱敏测试证据。首轮不以门锁、加热、摄像头/麦克风、运动机构或连接未知负载的插座做执行实验。“开关”动作是否低风险取决于其实际负载。

## 职责和配置归属

| 所有者 | 负责 | 不负责 |
|---|---|---|
| 外部身份/域系统 | 谁可代表哪个人/域、授权来源与撤销 | 设备协议、网关连接和物理证据 |
| 平台 | 外部引用校验、设备/能力登记、资源授权、绑定、命令及审计 | 生成家庭关系、保存人物记忆、让 Agent 指定连接地址 |
| Edge | 精确路由、协议秘密加载、现场约束、日志、防重放、证据上传 | 从自然语言生成目标、自动接管另一个 Edge 的写权限 |
| 型号专用 Adapter | 原始协议与平台能力的映射、读回和错误分类 | 自行决定人/域权限或把网络应答提升成物理完成 |
| Broker / 协议网关 | 网络身份、传输保护与最小设备/主题权限 | 替代平台业务授权或证明动作已经完成 |
| 现场操作者 | 核对实体目标/负载、批准测试窗口、执行现场安全停机 | 因平台显示成功就省略独立检查 |

Agent 在云端、手机或音响上，不改变这些职责。家庭/人的域引用与设备所在网络/协议 fabric 必须分开；MQTT namespace 不是人的域，更不是授权机制。

## MQTT 设备的附加要求（仅当型号选择 MQTT）

不沿用无认证演示 Broker，不桥接其 `agenticiot/demo/...` 主题到真实设备。Broker 产品和版本待接入卡确认，不提前绑定某一服务商。

1. Edge 与设备各有独立认证身份；显式禁用匿名访问，验证服务端证书和名称。采用受保护传输，客户端证书或独立凭证方案按设备实际支持情况决定。
2. 先列出厂商真实主题，再授予最小权限；不给 Agent 主题拼接、通配符和 Broker 管理权限。只读凭证不能继承写命令权限。
3. 权限矩阵基于“操作意图”而不是一套通用主题：设备只能上报自身状态，Edge 只能读取被分配设备；C 阶段才追加该设备的允许动作。反向伪造状态、跨设备访问和管理主题访问均应拒绝。
4. 只读优先订阅遥测。如果协议必须发布查询才能读取，则只授予经过核实、没有控制副作用的查询路径；查询与控制共用主题且 Broker 无法区分时，不能仅靠主题 ACL 声称只读隔离，需要额外受信任校验或改用被动读取。
5. 不发送保留控制指令；对历史保留状态保留原始新鲜度。核对设备与 Broker 的重连/会话持久化是否会重放旧命令，不把库默认行为当成安全保证。
6. 凭证撤销须验证既有连接也失去权限，而不只是新连接失败；路由/身份变化必须先停写并评审在途命令，不能原地替换目标继续执行。

Mosquitto 文档区分连接认证与主题访问控制，并指出用户名/密码应配合网络加密；这支持上述职责分离，但并不意味着项目已配置或验收 Mosquitto。[认证说明](https://mosquitto.org/documentation/authentication-methods/)、[配置手册](https://mosquitto.org/man/mosquitto-conf-5.html)。

若老设备无法提供足够认证/传输保护，需要另行评审隔离网关及残余风险；网关可信不等于网关后的设备已获得端到端认证。不得静默关闭证书校验或直接开放控制。

## 什么可以算成功

- Broker PUBACK、HTTP 200 或厂商返回“收到”只证明相应通信阶段，不能自动成为物理完成证据。
- 相关读回必须说明来源、目标、时间/序号及关联强度。若设备没有命令 ID，且存在多个控制者，“当前值等于目标”不能证明是本次命令产生的效果。
- 不把 Edge 收包时间伪装为设备观测时间，不把轮询缓存包装成 fresh 状态。
- 在外部副作用与本地持久化之间崩溃时保留不确定结果，不默认自动重发；是否能安全重试取决于该型号的动作语义和实际去重支持。
- 如果证据无法满足当前 `confirmed` 语义，必须先修改并评审确认模型，不能在 Adapter 内伪造关联 ID 来通过平台检查。
- 当前模拟结果模型不能直接表达所有真实设备的证据质量和停止状态；应在确定设备后仅添加该型号确实需要的最小字段/状态。

## 故障验收矩阵

全部初始状态为 **未执行**。模拟器测试通过不能代替下表的真实设备验收；保留脱敏证据、实际版本和操作者记录。

| 测试 | 通过标准 | 阶段 |
|---|---|---|
| 目标核对 | 错误型号/身份/协议映射拒绝；不能操作另一个设备 | B、C |
| 未授权 / 只读写入 | 无凭证、错误凭证、只读身份均不能发送控制 | B |
| 错误证书 / 错误主机 | 连接被拒绝；没有不安全回退 | B |
| 跨设备 / 跨域 / 反向伪造 | 无权访问，不能上传其他设备证据 | B |
| 历史缓存 / 重复状态 | 不刷新采样时间，不将历史值当新读取 | B |
| 设备 / Broker / 网关离线 | 可见状态陈旧或未知，不制造新观测 | B |
| 凭证撤销 | 在约定且经实测的时限内失去访问；现有连接同样受限 | B |
| 错误参数 / 超时前未发出 | 拒绝动作，不继续投递过期命令 | C |
| 重复投递 / Edge 重启 | 有真实去重证据则只执行一次；无证据则不自动重发未知动作 | C |
| 设备已动作、回包丢失 | 显示结果不确定，不断言“未执行” | C |
| 另一控制者改变状态 | 不将巧合匹配或无关观测确认成本命令成功 | C |
| 设备自身重启 / Broker 持久会话恢复 | 无过期控制重放；设备恢复行为与接入卡相符 | C |
| 现场停写 / 撤销 / 恢复 | 不再发起新控制，保留在途审计；不宣称撤销等于物理回滚 | C |
| 隐私与日志 | 令牌、证书私钥、原始私人数据不出现在 API、日志或截图 | B、C |

“停止发出新的命令”不等于能停止已发生的物理过程；必要的现场隔离/断电/机械安全措施由设备用途决定，不依赖本平台替代。
