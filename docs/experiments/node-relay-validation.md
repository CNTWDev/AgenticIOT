## 实验前固定的条件

平台部署到获准的真实云主机，Node 位于家庭宽带 NAT 与 Wi-Fi 后；直连客户端在同一家庭网络，比较相同 Node、模型、输入长度、输出上限及设备。localhost 只用于调试，不作为云中转结论。不得为了实验自动购买云资源、上传私人 prompt 或控制未经授权的硬件。

运行前记录代码版本、地区、云与家庭 RTT/丢包、机器和模型版本、Wi-Fi 条件、并发与队列限额、超时、采样频率和驱动。纯推理使用合成文本。参考网络选择云到家庭 RTT p95 不超过 150 ms 的配置；超出时作为另一组网络条件报告，不能混入参考组。

以下为本次设计提出的初始工程预算，需在第一次运行前由实验负责人确认并写入运行记录。它们不是已测得性能或正式产品 SLA。变更预算必须发生在对应新实验前，保留原预算与失败结果。

| 指标 | 参考组初始通过预算 |
| --- | --- |
| 预热文本生成的配对首内容时延增量 | p95 不超过 500 ms |
| 平台持久化接受命令至 Node 接收 | p95 不超过 500 ms |
| 在线、低延迟参考设备的请求至相关证据返回 | p95 不超过 2 s；真实硬件另报自身耗时 |
| 13 个读取各延迟 2 s 的不可读绑定，加一个独立在线目标 | 在线目标命令仍满足以上派发预算；接收不等待全量读完 |
| 同时提交至少 7 个在线目标命令，命令期限 30 s | 无因每轮仅领取一条产生的过期；跨设备有界重叠执行且同设备动作不乱序 |
| 2 个推理流同时输出及 1 个慢消费者 | 控制消息仍满足派发预算，缓冲不超过预先配置上限；明确限流不计作成功 |

## 测量方式

TTFT 定义为客户端开始请求至收到首个实际文本内容，不能用响应头或空 role chunk 充当首 token。使用同一客户端单调时钟测量端到端时间；跨机分段需记录时钟偏差，不能直接相减未校准时间戳。

预热组每种负载至少 100 对直连/中转请求，交替或随机顺序，避免一组独占冷缓存；冷启动另做至少 10 对，明确如何确认模型已卸载和缓存状态。并发组按单流及限定并发分别运行，不在一次资源竞争中误将直接调用当作无干扰基线。

逐对计算 `delta_i = relay_TTFT_i - direct_TTFT_i`，报告差值的 p50/p95，以及两组原始时延、失败率和置信范围；不能只用两个 p95 相减冒充配对 p95。该差值是观察到的中转路径增量，包含网络及残余模型波动，并非纯后端 CPU 开销。

记录入口到平台、平台准入、平台到 Node、Node 到模型首输出及返回链路的可测分段；同时报告输出速率、总完成时间、队列深度、控制派发时延和峰值内存。模型冷启动及加载成本独立列出。

## 复现与故障矩阵

- 原轮询基线：13 个 broker 可达但设备不响应的绑定；与命令不同提交相位组合。另测一次提交 7 条及更多命令。记录过期比例，不预先宣称每次必定过期。
- 新调度：分别测试跨 Binding 并发、同 Binding 串行、共享适配器串行限制和日志线程安全。无法满足资源容量时明确拒绝或受限排队，不能用无限并发达标。
- 事件：采样间隙开关恢复应显示未捕获或无事件，不能捏造；原生订阅断连显式产生缺口记录。事件重放去重、权限撤销和晚提交游标不能丢失已摄取事件。
- 推理：断开客户端、断开 Node、杀死所属进程、停止模型；已有输出不拼接新模型，unknown 不自动重发，重试相同键不再派发。无正文写入数据库、常规日志或持久化代理缓冲。
- 生命周期：限时排空、旧代次拒绝新派发、原命令证据重连补报、失联实例 unknown 判定不影响存活实例。

## 判定与后续

报告每组通过数、样本数、失败分类及全部预算，不以平均数隐藏尾延迟或排除超时样本。真实硬件未接入时，设备结果明确标为模拟参考，不计为 ADR 0007 完成。

未达预算先定位网络、队列、采样阻塞或模型差异，再决定限流、优化或重新评审云路径；不自动增加云备用、离线授权或多实例。通过只对记录的配置与负载有效。实验开始前仍需落实云主机、测试 Node、本地模型、设备目标及相关授权；本计划不表示这些条件已经具备。
