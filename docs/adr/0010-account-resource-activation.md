# ADR 0010 账号身份与资源激活

日期：2026-10-02。状态：Accepted。补充 ADR 0009，不建立平台自有用户注册系统。

## 决策

资源进入管理和调度之前，必须有可验证的管理主体、明确的资源域及有效授权。人账号和服务账号由入口的可信身份系统管理；平台识别其发行方、客户端和主体，使用同一 Access 边界。不为设备管理和本地服务注册各建一套账号系统。

账号回答“谁在管理”，Domain 回答“资源归谁隔离”，Grant 回答“允许做什么”。一个人可在多个域获得授权，一个域可有多个人或服务主体；资源不因管理员退出或更换入口而迁移。首版不实现家庭成员关系或自动跨入口关联。

## 激活规则

- 初始入口别名及主体授权由受控引导命令建立。签名合法本身不创建域或授予权限；重复引导不恢复已撤销 Grant，也不扩大现有权限。
- 有 `domain:manage` 的主体可登记 Node、绑定设备、注册和批准本地服务；不能增加自身授权上限、建立跨入口共享或操作其他域。
- 登记 Node 签发一次性展示的随机机器凭证。平台仅存摘要，凭证在可信配置时交给 Node；首次连接证明持有凭证，不声称证明硬件出厂身份或物理所有权。
- Node 使用机器凭证建立 WSS，不能用它调用用户或管理接口。停用和轮换独立于在线状态；轮换不自动重新启用已停用 Node。
- 设备先注册为待接入，再由管理主体显式绑定获准 Node；当前只允许已有模拟灯具适配器。不能把 BLE、ZigBee 等无账号能力的末端设备强行变成用户账号。
- 本地服务注册为禁用状态，随后显式批准启用。每个服务只绑定本域 Node、一个本机配置标识及获准模型；Node 再检查本机端点与模型白名单。
- 管理账号、Node 机器凭证、服务目录记录是三个对象；首版不托管第三方云模型账号或密钥。

有效权限为已验证令牌权限、平台当前 Grant 和资源安全规则的交集。静态开发凭证也经过内部域映射和 Grant 校验。域内管理员可撤销本域 Grant，但没有提升、重新授予或重新启用 Grant 的自助 API。

## 实现与限制

内部域迁移保留原资源 ID、型号引用和历史记录，不删库。旧响应字段 `domain_ref` 暂为兼容名称，其值已是内部 ID；新的 Access、Node 和服务接口使用 `domain_id`。入口提交的外部域只存在于令牌和 DomainAlias 中。

`0005_access` 是有损降级保护点：多个外部别名可能关联一个内部域，不能自动选择旧字符串恢复归属。升级前备份；跨越该点回退需恢复备份，不能执行自动降级或删库重建。

本次交付最小管理 API 与后台，不包含公开账号注册、绑定二维码、厂商激活码或跨入口授权界面。C 端产品可由获准可信后端调用管理 API；新域的批量引导及跨入口共享仍需产品侧明确流程与授权，不能靠传入相同域名实现。
